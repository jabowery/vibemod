The Elixir handler supports:

Target path formats:

MyApp.Users → module
MyApp.Users.SubModule → nested module
MyApp.Users.get_user → function in module
MyApp.Users.get_user/1 → function with specific arity
MyApp.Users.defp:validate_email → private function
target@N → Nth occurrence

Features:

Indexes defmodule, def, defp, defmacro, defmacrop, defguard, defguardp, defstruct, defprotocol, defimpl, defexception
Tracks function arity
Attaches @doc and similar attributes to functions
Skips module-level attributes like @moduledoc, @behaviour, @callback
Syntax validation using tree-sitter
Duplicate module detection
In the case of MMM update_header MMM, if the first statement in the content is a defmodule, the behavior should be to treat the content as the new content of that defmodule up to the first def* within that defmodule.  Otherwise update_header works as usual (ie: the file contents up to the first def* becomes the contents of the update_header directive).
