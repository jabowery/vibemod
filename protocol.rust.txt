
Rust allows multiple declarations of the "same" symbol name in a file (e.g., multiple `impl Type {}` blocks; cfg-gated duplicate items; trait impls). Therefore:

1) NEVER assume a symbol name is unique.

2) When modifying Rust declarations, ALWAYS target the exact item kind and anchor:
   - Use `impl:TypeName.method_name` or `impl(TypeName).method_name` for inherent methods.
   - Use `impl:TraitName for TypeName.method_name` for trait methods.
   - Use `impl(TypeName)#[cfg(...)]...` when cfg-gated.

3) If there may be multiple matches, add an occurrence selector `@N` (1-based) OR design the change so "replace all matches" is correct.
  Oh... did I not mention that the N in @N is 1-based?  It is 1-based.

4) When adding a new method to an existing impl block, do NOT emit a bare `fn` at module scope and do NOT wrap the method in `impl Type { }`. Target `impl:TypeName.method_name` directly (vibemod will insert into the impl block).

5) Always provide COMPLETE Rust items. No partial snippets.

6) For test-only helpers, prefer:
   - `#[cfg(test)] impl TypeName { ... }`
   and target paths using `impl(TypeName)#[cfg(test)].method`.

7) Default insertion behavior:
   - New top-level declarations (fn, struct, impl, etc.) default to end of file
   - New methods in impl blocks insert at end of the impl block
   - Explicit anchors available when needed: `@append_file`, `@insert_after(ItemName)`, `@insert_before(ItemName)`

8) For inserting statements INSIDE a function or method body (e.g., adding a `let` binding), use scoped insertion:
   - `function_name.@after:let x = 1;` - insert after the statement `let x = 1;` inside `function_name`
   - `function_name.@before:let y = 2;` - insert before the statement
   - `impl:TypeName.method.@after:let z = 3;` - insert inside a method
   
   Also:
   - `function_name.@after:"assert!(\s*max_level "@2
   would insert after the second assert statement that looked like this:

    assert!(
        max_level >= 2,
        "precondition: expected emergent level>=2 action; saw max_level={}",
        max_level
    );
    
   Scoped insertion automatically handles indentation and removes conflicting declarations of the same symbol in that scope.

9) Target path normalization: You may include the declaration keyword (e.g., `fn foo()`, `struct Bar`) but the canonical form is just the name.

Output MUST be vibemod directives only.
